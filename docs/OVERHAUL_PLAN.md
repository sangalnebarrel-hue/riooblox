# DOGROTS — большое обновление: аудит и план

Документ фиксирует результаты аудита плейса `DOGROTS_MINING_5.rbxl` (побайтно совпадает с
`build/DOGROTS_MINING.rbxl` на коммите `d38d853`) и план переработки. Резервная копия:
`backup/DOGROTS_MINING_5_before_overhaul.rbxl` и git-тег `pre-overhaul-v5`.

## 1. Аудит

### 1.1 Структура и сборка

- Плейс собирается из `place/DOGROTS_base.rbxl` и всех скриптов `src/` (`tools/build.py`).
  Сборщик меняет только `Source` скриптов и добавляет Script/LocalScript/ModuleScript/Folder.
  Поэтому **вся новая геометрия строится кодом во время игры** (так уже сделаны мини-шахта,
  витрина находок, обновления района), а новые RemoteEvent создаются в рантайме.
- В плейсе 33 тыс. деталей, 1730 ModuleScript (из них ~1390 — клипы анимаций), 342 скрипта
  с логикой (68 тыс. строк Luau), `StreamingEnabled = true` (радиус 64…1024).
- Проверка: `tools/check.sh` — сборка, сверка исходников через Lune, 13 наборов юнит-тестов,
  статический анализ luau-lsp (только новые замечания). До начала работ: всё зелёное.

### 1.3 Что улучшаем поверх, а что требует аккуратного рефакторинга

**Поверх текущих систем (без изменения данных):** навигация, звуки и анимации UI, «Скрыть UI»,
титулы (новые поля + старые `Cosmetics` засчитываются), украшения участков (новое поле),
витрина (новое поле, авто-подбор остаётся запасным), новые модели находок (тот же `ItemId`),
шахта (визуализация существующих 5 слоёв), Dog Rush (клиентская часть ивента), баланс
(конфиги), машина мутаций (поверх `LabPreview/LabCommit`).

**Аккуратный рефакторинг:** инвентарь (новое Kit-окно вместо статичной страницы), окно обмена
(новое Kit-окно; протокол сервера расширяется совместимо), окно лаборатории (старое остаётся в
коде как откат через `LabConfig.SimpleMode`), размещение собак в будках при глубине ≥ 2
(модели собак переносятся в забой шахты, данные не меняются).

**Что не меняется в данных:** имена вариантов собак, мутаций находок, ID предметов, формат
`p.Dogs`/`p.Items`, `p.Lab` (ДНК и история остаются валидными), `MegaResetVersion`.

## 3. Общие правила для нового кода

- Сервер: новые данные и действия — модули `src/ServerScriptService/Economy/Features/<X>.luau`
  (`Normalize`/`Validate`/`Action`/`Snapshot`, см. `FeatureRegistry`). `Normalize` дешёвый и
  идемпотентный (вызывается каждую секунду), `Validate` принимает `nil`. Только строковые ключи.
  Цены — только с сервера.
- Клиент: окна — Kit (`docs/UIKIT.md`) в `src/StarterGui/ScreenGui/Modules/<X>Screen.luau` c
  `Open(arg)`; маршруты `Inventory/Trade/Navigate/Titles/Showcase/Decor/Mine` уже ведут в эти
  модули (`GUIIntegration.kitScreens`). Данные — `Modules.Net`.
- Тексты: английские строки + `ReplicatedStorage/Localization/<Feature>.luau` (русский).
- 3D из кода: `ReplicatedStorage/Forge.luau`; детали без коллизий по умолчанию, LOD через
  `b:Detail`, акценты через `b:Accent`. Превью без Studio: `tools/qa/scene.luau` + `tools/qa/render.py`.
- Эффекты — на клиенте, с пулами и бюджетами, без покадровых циклов в простое; всё, что
  подключено, отключается (`Maid`).
- Ресурсы: `ReplicatedStorage/DogEconomy/Resources.luau` (`p.Resources.Stone`).
- Тесты: `tests/<feature>.luau` (Lune, `tests/lib/economy_env.luau`), запускаются `tools/check.sh`.
