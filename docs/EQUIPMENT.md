# Экипировка: артефакты собак, аксессуары игрока и магазин экипировки

Коротко: здание **UPGRADES** на Лапа-рынке (Paw Market) стало **магазином экипировки (EQUIPMENT)**.
В нём две чётко разделённые вкладки:

| Вкладка | Кого усиливает | Где носится |
|---|---|---|
| **PLAYER ACCESSORIES** (аксессуары игрока, голубая, ★) | **тебя**: всех твоих собак и твой доход | по одному в слоте **шапка / лицо / спина / аура**; виден на персонаже всем игрокам |
| **DOG ARTIFACTS** (артефакты собак, оранжевая, 🐾) | **одну собаку** — ту, на которой надет | в слотах конкретной собаки; число слотов зависит от редкости собаки |

Предметы выпадают из **кейсов** (монеты, кости или ключи за Robux). Ненужное можно
**разобрать на кости**, ценное — **защитить** от разбора. Всё проверяет сервер, старые сохранения
не меняются (новое поле `p.Equipment` просто появляется у профиля).

## Как играть

1. Подойди к терминалу внутри здания (подсказка **OPEN EQUIPMENT · SERVICE TERMINAL**).
2. Слева (на телефоне — вкладка «КЕЙСЫ») — кейсы: цена на кнопке **OPEN**, кнопка **ODDS %** с точными
   шансами каждой редкости, полоска гарантии («ЭПИЧЕСКИЙ+ ГАРАНТИЯ ЧЕРЕЗ 12»).
3. Открытие: кейс трясётся и раскрывается, лента предметов прокручивается и останавливается на
   выпавшем (лента — честные случайные выпадения с теми же шансами, без «почти выиграл»), вспышка
   цвета редкости, карточка награды: предмет в 3D, бонус («+3.54% УДАЧА»), кого усиливает,
   качество. Кнопки: **НАДЕТЬ** / **НАДЕТЬ НА СОБАКУ**, **ЕЩЁ РАЗ** (с ценой), **ЗАБРАТЬ**.
   **ПРОПУСТИТЬ** (или Escape / B на геймпаде) сразу показывает награду. С включённым в Roblox
   «Reduced Motion» карточка появляется без анимации.
4. «МОЯ СУМКА»: фильтры по слоту/характеристике и редкости, сортировка (редкость, бонус, новые),
   нажатие на предмет — подробности: бонус, что он делает, диапазон и качество броска,
   НАДЕТЬ / СНЯТЬ, ЗАЩИТИТЬ, РАЗОБРАТЬ (с удержанием кнопки).
5. Артефакт на собаку: «НАДЕТЬ НА СОБАКУ» → выбрать собаку → выбрать слот («ПОСТАВИТЬ СЮДА»).
   Если слот занят, игра спросит подтверждение и покажет, что старый артефакт вернётся в сумку.
   Кнопка **ВЫБРАТЬ СОБАКУ** во вкладке артефактов открывает слоты любой собаки.

### Слоты артефактов по редкости собаки

Обычная 1 · Редкая 2 · Эпическая 2 · Легендарная 3 · Мифическая 3 · Секретная 4
(`EquipmentDefinitions.DogSlots(def | rank | rarity)`). Закрытые слоты показаны с замком и
подписью «Нужна собака ЛЕГЕНДАРНЫЙ+».

## Каталог (значения из `ReplicatedStorage.DogEconomy.EquipmentDefinitions`)

Значение предмета = `Min + (Max − Min) × Roll`, где `Roll` — качество броска 0…1 (у каждого
экземпляра своё, видно как «КАЧЕСТВО 87%»). Значения — доли бонусов `Bonuses`: 0.10 = +10%.

### Разбор и защита

Разбор даёт кости: Обычный 2 · Необычный 4 · Редкий 9 · Эпический 20 · Легендарный 45 ·
Мифический 110. Разобрать нельзя надетые и защищённые (🔒) предметы. За один запрос — до 30
предметов (режим «РАЗОБРАТЬ» в сумке, кнопка «ВЫБРАТЬ ВСЁ» берёт только свободные). Ни один кейс
в среднем не возвращает больше 40% своей цены в костях (проверяется тестом).

Вместимость сумки: 120 артефактов и 80 аксессуаров. С полной сумкой кейс не откроется
(и ничего не спишется); ключи за Robux при этом не теряются.

## Robux-ключи (платные случайные предметы)

Сейчас **ничего не продаётся**: все продукты в `EquipmentDefinitions.Products` имеют `Id = 0`,
`Enabled = false`. Чтобы включить продажу:

1. Creator Hub → твоя игра → **Monetization → Developer Products** → создать продукты, например:
   «Mythic Vault Key» (49 R$), «5 Mythic Vault Keys» (199 R$), «Star Trunk Key», «5 Star Trunk Keys».
2. Вписать их ID в `ReplicatedStorage.DogEconomy.EquipmentDefinitions` → `E.Products`
   (`Key` не менять!) и поставить `Enabled = true`. Поле `Robux` — только подсказка для экрана,
   игрок всегда платит цену из Roblox (её экран запрашивает у `MarketplaceService`).
3. Пересобрать плейс. При старте сервера `PurchaseService` сам подключает каталог
   (`Features.Equipment.Catalogs` → `RegisterCatalog`), а аудит в Output проверит, что ID
   принадлежат игре. **Не удаляйте** проданный ID из списка — иначе его чеки повиснут.

Как это работает (правила Roblox для платных случайных наград):

* Перед покупкой всегда открывается окно **шансов** кейса с кнопкой «КУПИТЬ КЛЮЧ · R$ …».
* Кнопки покупки показываются только если `PolicyService` разрешает этому аккаунту платные
  случайные предметы (`PaidRandomPolicy`; ответ кэшируется, снимок не ждёт `PolicyService`).
* Чек (`PurchaseService`, одна транзакция «выдача + отметка чека + TOP SUPPORTERS») выдаёт
  **только ключи** (`p.Equipment.CaseCredits[caseId].Paid`), предмет при покупке не выпадает.
* Открытие — отдельное действие. Сначала тратятся бесплатные ключи, платные — только если
  политика разрешает (иначе «…unavailable for this account; your keys are kept», ключи остаются).
  Предмет из платного ключа помечается `PaidRandom = true` (для будущих обменов/рынка).
* Другие системы могут выдавать **бесплатные** ключи как награду:
  `require(Economy.Features.Equipment).GrantCredits(p, "RelicChest", 1, false)` внутри своей транзакции.

Проверка в Studio без Robux (Play, командная строка в режиме **Server**, при временно вписанном
ID продукта): `game.ServerStorage.DOGROTS_HandleReceipt:Invoke({PlayerId=<id>, ProductId=<id>,
PurchaseId='studio-eq-1', CurrencyType=Enum.CurrencyType.Robux, CurrencySpent=49})` — в магазине
появится «ОТКРЫТЬ · 1 КЛЮЧИ», повтор того же `PurchaseId` ничего не добавит.

Кейсы за монеты и кости (которые тоже бывают в Robux-наборах) по рекомендации аудита
монетизации не закрываются политикой: шансы показаны, это неплатный путь для всех аккаунтов.
Если владелец решит иначе, достаточно добавить проверку `PaidRandomPolicy` в `openCase` для `Pay = "Bones"`.

## Внешний вид

* Все 48 предметов и 6 кейсов собраны из деталей (`EquipmentVisuals`, без внешних ассетов):
  2–7 деталей на предмет. Редкость задаёт «акцентные» детали: цвет редкости и материал
  (обычный пластик → стекло → неон), у легендарных и мифических в мире — мягкий свет, у
  мифических — немного искр. В интерфейсе предметы показаны в ViewportFrame (кэш `Kit.Preview`).
* Надетые аксессуары видят все: сервер приваривает модель к персонажу (`Economy.EquipmentWorld`,
  запускает `ServerScriptService.EquipmentAvatar`). Детали без массы, без столкновений и
  касаний, не более 28 деталей и двух источников света на игрока. Модели живут внутри персонажа,
  поэтому после смерти/выхода исчезают сами, а при возрождении надеваются снова.
* Здание UPGRADES: имя модели не менялось (на него ссылаются скрипты), сервер меняет надписи
  (EQUIPMENT, EQUIPMENT TERMINAL, GEAR UP YOUR PACK, DOG ARTIFACTS, PLAYER ACCESSORIES, CASES)
  и ставит на прилавки три витринных предмета. Подсказка терминала — **OPEN EQUIPMENT**,
  в карте — «Equipment, cosmetics and supplies». Русские надписи — `Localization/Equipment`.

## Для разработчиков

### Данные профиля (`Economy.Features.Equipment`)

```
p.Equipment = {Version=1, Next=n, Rev=n,
  Artifacts   = {[uid]={Uid, Id, Rarity, Roll, DogUid?, Slot?, CreatedAt, Origin, PaidRandom?, Locked?}},
  Accessories = {[uid]={Uid, Id, Rarity, Roll, Slot?, CreatedAt, Origin, PaidRandom?, Locked?}},
  CaseCredits = {[caseId]={Free=n, Paid=n}}, Seen={[id]=true}, Pity={[caseId]=n}, Opened={[caseId]=n}}
```

* Артефакт **не хранится внутри собаки**, он указывает на неё (`DogUid`). Если собака ушла из
  профиля (лаборатория, обмен, рынок, приют), `Normalize` снимает указатель — артефакт просто
  возвращается в сумку. Ничего не дублируется и не теряется.
* `Normalize` также чинит: слот больше, чем у собаки; два артефакта в одном слоте (остаётся
  меньший uid); аксессуар не в своём слоте; качество вне 0…1; отрицательные ключи. Ни один
  предмет не удаляется. `Validate` проверяет только тип (`p.Equipment` — таблица), чтобы
  никогда не отклонять то, что чинит `Normalize`.
* `Rev` растёт при каждом изменении — по нему `BonusSources.Artifacts` перестраивает индекс
  «собака → артефакты» (один раз на транзакцию, а не на каждую собаку).

### Действия (DogEconomyRequest → Rules.Action → фича)

| Действие | Аргументы | Ответ |
|---|---|---|
| `EquipmentOpenCase` | `{Case, Pay='Cash'\|'Bones'\|'Credit', Quote?}` | `{Opened={Kind,Uid,Id,Rarity,Roll,Stat,Value,New,Pity?,PaidRandom?}, Reel={ids…}, WinIndex, Case}` |
| `EquipArtifact` | `{Uid, DogUid, Slot}` | `{Equipped, Replaced?, MovedFrom?}` |
| `UnequipArtifact` | `{Uid}` | — |
| `EquipAccessory` | `{Uid}` | `{Equipped, Replaced?}` |
| `UnequipAccessory` | `{Slot}` | — |
| `SalvageEquipment` | `{Uids={…}}` (1…30) | `{Bones, Count}` |
| `LockEquipment` | `{Uid, Enabled}` | — |

Сервер проверяет всё: владение предметом и собакой (`R.Dog`), номер слота по рангу собаки,
вместимость сумки, оплату (`R.Pay`), политику для платных ключей, повторы uid, лимит открытий
(4 за 2 с на игрока, в памяти сервера). Броски делаются внутри транзакции генератором сервера.

### Бонусы

`ReplicatedStorage.DogEconomy.BonusSources.Artifacts` (`Dog`: только артефакты этой собаки,
с потолками) и `...Accessories` (`Global`: надетые аксессуары). Они идут через общий конвейер
`Bonuses`: скорость → `Rules.Cooldown`, удача/редкие находки/мутации → находки, доход/сила/деньги →
стоимость выкопанного (фиксируется на предмете при находке), опыт, офлайн-доход
(`OfflineEarnings`). `R.Bonus` (цена приюта) и `R.Credit` не затронуты — экипировать и продать
ради выгоды нельзя. `Snapshot.DogStats` уже учитывает артефакты каждой собаки.

### Снимок для клиента

`snapshot.Features.Equipment = {Artifacts, Accessories, CaseCredits, Cases, PaidAllowed,
PaidKnown, DogSlots, Capacity, Equipped, ByDog, Rev}`. В `Cases` — серверные цены, шансы,
гарантия, ключи и (если продаются) Robux-продукты. `ByDog[dogUid] = {uid…}` — для значков на
карточках собак.
